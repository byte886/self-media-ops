# 运营策略层（SYSTEM STRATEGY）

> **文档类型**：Governance（业务方向与策略）
> **维护者**：AI 起草 + 用户拍板
> **读者**：AI 代理（业务意图任务必读）
> **定位**：本文件是"鉴藏（heritage）体系"的**意图层**，管"往哪去"（方向/选题/优先级）；系统运行机制与路由在采集底座 `multiplatform-content-pipeline/docs/SYSTEM_ARCHITECTURE.md`，管"怎么转"。
> **原则**：方向异步更新，**不阻塞下游**——各仓按自己的驱动点自治运作，产物就绪本层即可取用。

---

## 1. 业务起点（为什么从运营切入）

业务需求从**自动化运营**发起：要发朋友圈/要获客/要卖货 → 需要成片与素材 → 需要知识与情报。
本层是需求起点，向下游派**方向**（不是派指令）：下游各仓（采集/调研/监控/生产）各有驱动点自主运作，不依赖本层完成才启动。

## 2. 定位与受众

- **受众**：线下珠宝购买客户（门店/私域），以朋友圈"AI 工作台"系列为首发内容线
- **内容载体**：朋友圈图文、短视频成片（由生产层供给）、小红书/抖音平台内容（排期 ADR-002 已定节奏）

## 4. 策略来源与选题管道

- **选题输入**（产物就绪即取用，不等待）：
  - 情报速递（monitor 定时扫描产物）→ 热点/趋势选题
  - 知识成品（pipeline 05_knowledge）→ 专业论据/科普素材
  - 成片/方案图（sop 生产产物）→ 发布内容
- **选题记录**：新选题写入 `project-management/TASK_STATUS.md`，确定后登记排期

## 5. 本层职责边界

| 本层管 | 本层不管（下游自治） |
|---|---|
| 方向：做什么内容/什么优先级 | 怎么查（toolkit 方法层） |
| 选题：内容主题与排期 | 怎么采（pipeline 采集驱动） |
| 发布：文案终审/发布节奏 | 怎么盯（monitor 定时机制） |
| 效果反馈：哪条爆/哪条哑 → 回流策略 | 怎么产（sop 生产门禁） |

## 6. 效果反馈回路

发布 → 观察点赞/评论/转化 → 记入 `ISSUES.md`（经验/坑）→ 回流本文件 §4 选题管道与排期 → 调整策略。
